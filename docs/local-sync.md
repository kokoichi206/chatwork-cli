# ローカル履歴同期（cw sync）設計メモ — 未実装

2026-07-16 の議論で方針合意済み。v1 スコープ外として切り出し。

## 背景・動機

Chatwork API の `GET /rooms/{room_id}/messages` は**最新 100 件のみ・ページネーションなし**。
このため:

- 「この部屋の情報を全部読んで判断して」という agent タスクは、API 直叩きでは 100 件で頭打ち
- `force=0` の差分カーソルは**サーバー側でトークン単位**に保持されるため、
  agent と人間・複数ツールが同じトークンを使うと差分が食い合い「どこまで読んだか」が壊れる
  （現状 `cw messages read` の既定を `force=1` にしているのはこの回避のため）

→ 履歴を積み上げる場所はローカルしかなく、ローカル蓄積は過剰ではなく唯一の解。

## 設計

### コマンド

```
cw sync <room|--all>
  force=1 で最新 100 件取得 → ローカル履歴と message_id で dedupe → 新着のみ追記
  出力(JSON): {"room_id":..., "new": <新着件数>, "gap": <bool>, "messages": [<新着分>]}

cw messages read <room> --local [--since YYYY-MM-DD] [--all]
  ローカル履歴から読む(API を叩かない)
```

- `sync` の返り値が新着分そのものなので、agent は「作業開始時に sync → 差分だけ判断」が自然に書ける
- どこまで読んだかの状態はローカル履歴との突き合わせで決まり、サーバー側カーソルに依存しない

### 保存先

XDG の役割分担に従う（設定 = .config、データ = .local/share）:

```
~/.local/share/chatwork-cli/<account_id>/rooms/<room_id>.jsonl
```

- 1 行 1 メッセージの JSONL、message_id を主キーに upsert
- account_id をパスに含める（複数アカウントで同じ部屋に入っていても混ざらない）

### gap 検知

sync 間隔が空いて投稿が 100 件を超えると、溢れた分は永久に取得不能（API 制約、回避不能）。
「ローカルの最新 message_id が今回取得した 100 件の中に存在しない」ことで欠落を検知できるので、
`"gap": true` を返して agent に知らせる。埋めることはできない。

### 制約（明記しておくこと）

- 編集されたメッセージは message_id 一致 + update_time 差分で上書きできる
- 削除されたメッセージはローカルから消えない（削除の検知手段が API にない）
- レート制限（300 回/5 分）があるため `--all` は部屋数が多いと数分かかりうる

## 実装しない判断をしたこと

- サーバー側カーソル(`force=0`)による差分同期 → トークン共有で壊れるため不採用
- ローカル DB(SQLite 等) → JSONL で十分。検索が必要になってから検討
